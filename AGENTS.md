# HW06 Agent Instructions

## Project Scope

- This repository is an individual FIT@HCMUS Software Testing HW06 submission.
- The selected APIs are fixed unless the student explicitly changes them:
  - Pool A: `POST /api/register` (FR-01).
  - Pool B: `POST /api/checkout` (FR-08).
  - Pool C: `POST /api/admin/coupons` (FR-17).
- Use Postman and Newman for API execution and GitHub Actions for CI/CD.
- Store test cases in `test-cases/API_Test_Cases.csv`.

## Sources of Truth

Read these before starting or resuming work, in this order:

1. `2026.HW06.API Testing_En.md` for submission and grading requirements.
2. `README.md` for correct business requirements and security rules.
3. `api_specification.md` for endpoint contracts.
4. `Plan.md` for approved decisions, current state, completed work, and the next action.
5. Actual file state, Git diff, Postman/Newman output, screenshots, and CI runs for execution evidence.

If sources conflict, report the conflict. Do not invent a resolution or repeat work that already exists.

## Start-of-Work Protocol

Before changing files:

1. Read `Plan.md` completely.
2. Inspect `git status --short` and the target files.
3. Confirm the next unchecked item in `Plan.md`.
4. Reuse existing Postman requests, CSV rows, reports, and scripts instead of recreating them.
5. Treat unverified claims as pending, even if a previous response said they were complete.

## Testing Rules

- Do not modify the SUT backend to hide or make a defect pass unless the student explicitly requests a fix.
- Separate product defects from test-script, environment, data, and timing failures before reporting a bug.
- Every request must include `X-Student-Id: 23127280` through the Postman environment/pre-request script.
- Generate at least 35 AI-assisted cases and add at least 5 human-designed cases for each selected API.
- Audit every AI-generated case as `VALID`, `INVALID`, or `INCOMPLETE`, with evidence and corrections.
- Use unique emails and coupon codes based on student ID plus a timestamp to isolate runs.
- Never fabricate screenshots, Newman output, CI runs, GitHub Issues, execution results, or human approval.
- The AI test-generator diagram must be designed and drawn by the student, not generated by AI.

## Repository and Privacy Rules

- Never commit tokens, cookies, passwords beyond the SUT's public demo credentials, private paths, or unsanitized Postman environments.
- Keep committed `userToken` and `adminToken` values empty.
- Do not stage `backend/database.sqlite`; it is runtime state already tracked by the upstream repository.
- Do not commit `node_modules`, caches, temporary reports, or local Postman state.
- Commit required deliverables: sanitized collection/environment JSON, CSV test cases, final Newman HTML, reports, and verified evidence.
- Prefer explicit `git add <paths>` over `git add -A`.

## Workstream Completion Protocol

After each workstream:

1. Verify outputs from files, commands, test results, or other observed evidence.
2. Update the current-state section and checklist in `Plan.md`.
3. Set exactly one concrete next action in `Plan.md`.
4. Add an approved decision to the `Plan.md` decision log only when the student explicitly accepts or selects it; never infer approval.
5. Update `AI_Audit.md` with exact available prompt/output text, file modifications, verification evidence, verdict, and human corrections.

Do not mark work complete because it was planned, described, or partially created.

## Test-Case CSV Contract

- Preserve the header in `test-cases/API_Test_Cases.csv`.
- Use IDs `REG-AI-###`, `CHK-AI-###`, `CPN-AI-###` for AI-assisted cases.
- Use IDs `REG-H-###`, `CHK-H-###`, `CPN-H-###` for student-designed cases.
- Quote CSV fields containing commas, quotes, or line breaks.
- Keep generated source, audit verdict, correction, actual result, execution status, bug ID, and evidence traceable in each row.

## Definition of Done

Work is complete only when the required artifact exists, its content has been verified, `Plan.md` reflects the result, `AI_Audit.md` records the workstream, and the relevant Git commit is identifiable.
