# FR-10 Test Execution

## Execution Scope

Teacher clarification: functional testing should be performed from the Frontend UI. Therefore, FR-10 execution uses Web User UI at `http://localhost:5173` and Admin UI at `http://localhost:5174` as the main oracle.

Backend/database setup was used only to prepare orders in specific states. API-only cases that cannot be triggered from UI are marked `Blocked`.

## Retest Data Setup

To recreate FR-10 test data after restarting the machine or resetting the database, run:

```bash
node test-data/seed-fr10-orders.js
```

The script deletes only previous orders whose `shipping_address` starts with `FR10-`, then inserts a fresh FR-10 dataset. Order IDs are generated by SQLite and may differ between runs, so use the printed mapping and the `FR10-*` shipping address labels when retesting.

## Execution Summary

- Total test cases: 32
- Passed: 20
- Failed: 7
- Blocked: 5
- Main failed areas:
  - Web User UI allows cancellation while order is `shipping`.
  - Admin UI allows a final `canceled` order to be marked as `delivered`.
  - User/Admin UI can show final-state inconsistency after cross-role actions.
